# Задание 5. Собственная служба systemd

## 1. Содержимое файлов

**Файл скрипта `/usr/local/bin/zagruzka-log.sh`:**
#!/bin/bash
echo "Система загружена: $(date)" >> /var/log/moya-zagruzka.log

**Файл юнита `/etc/systemd/system/zagruzka-log.service`:**
[Unit]
Description=Запись отметки о загрузке системы
After=multi-user.target

[Service]
Type=oneshot
ExecStart=/usr/local/bin/zagruzka-log.sh

[Install]
WantedBy=multi-user.target

## 2. Вывод команды systemctl status
Служба успешно запустилась и завершилась с кодом 0/SUCCESS. Статус inactive (dead) является нормальным для служб типа oneshot, так как они не должны висеть в памяти после выполнения.

## 3. Содержимое лог-файла /var/log/moya-zagruzka.log
После двух перезагрузок файл содержит две строки (пример):
Система загружена: Вт 27 окт 2026 01:08:49 +07
Система загружена: Вт 27 окт 2026 01:15:00 +07

## 4. Объяснение параметров
Type=oneshot — этот параметр означает, что служба запускается, выполняет свою задачу (в нашем случае — запускает скрипт) и сразу завершает работу. Systemd не должен следить за тем, чтобы процесс висел в памяти постоянно. Для скриптов, которые просто пишут лог и выходят, это идеальный тип.
WantedBy=multi-user.target — этот параметр в секции [Install] указывает, к какой цели (target) привязана служба. multi-user.target — это стандартный режим работы системы с поддержкой сети. Это означает, что когда система достигает этого этапа загрузки, она должна запустить и нашу службу. Благодаря этой строке команда systemctl enable создала символическую ссылку для автозапуска.
